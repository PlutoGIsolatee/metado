## 四、当前功能方案（现行行为）

**打包与校验**：构建将插件源码打包为签名产物；运行前校验签名与清单。

**治理**：装载时展开权限集、把授权收敛在请求范围内、对同名不同签名者拒绝、推进生命周期到可激活；激活后接受调用。

**执行**：运行时按「请求 ∩ 可用」导出命名空间，为每个方法生成「放行 / 拒绝」与「同步 / 异步」形状。放行即成功占位（同步给空值、异步给已定成功结果），拒绝即权限拒绝（同步抛出、异步被拒）。插件入口以默认导出对象的方法被调用，异步入口会被等待至定状态后再折叠返回值。

**返回值**：仅空值、布尔、数字、字符串可跨边界；数组、对象、字节暂统一折叠为空值。

**真实能力**：存储、日志、时间、随机数、哈希、文件、网络等能力的真实实现已作为可复用能力库存在，但**当前执行链路尚未调用它们**——插件得到的全是占位结果。

**Node 本地开发**：以本地套件复刻同一套授权匹配与「未授权拒绝 / 已授权占位」行为，供 Node 侧开发调试。

## 五、对外能力（按用途）

**插件作者可用**
- 在插件中按命名空间使用能力：网络、存储、文件、时间、日志、随机数/哈希、自定义能力、通用入口。
- 能力以同步或异步形状呈现；未请求的命名空间不可见；未授权调用被拒并指示权限名。
- 本地开发时可用 Node 套件复刻拒绝与占位行为。

**宿主/运维可用**
- 打包、校验、重签插件。
- 运行插件（真实执行入口）。
- 静态诊断：查看请求、可用、实际导出、入口表、缺失的宿主能力。
- 契约测试：按测试入口判定通过 / 失败。
- 执行观测：按类型查看执行轨迹（文本或 JSON）。
- 变更监听：目录变更后自动重建并运行。
- 守护进程管理面：加载、列出、授权、撤销、卸载、设生命周期、调用入口、取轨迹。

**待补齐的宿主能力（设计中）**
- 运行插件时真实产生存储、日志、时间、随机数副作用；存储目录可配；调用期二次裁决；日志输出通道区分；写入值串化。

## 六、预期用户交互场景

**S1 插件作者真实运行（设计目标态）**
声明存储读写、日志、当前时间、随机字节权限 → 构建 → 指定存储目录运行 → 日志输出、存储读回、真实时间、真实随机字节、入口返回值。

**S2 权限被拒**
未授权时：异步能力得到被拒结果，同步能力同步抛出；宿主二次裁决拒绝带统一前缀；未请求的命名空间整体不可见。

**S3 静态诊断 / 契约测试 / 执行观测**
分别查看能力与导出面、按测试入口判定通过失败、按类型查看执行轨迹。

**S4 Node 本地开发**
直接使用本地套件：授权后仍为占位（宿主无真实实现），未授权按同步/异步形状拒绝。

**S5 守护进程管理面**
经管理接口加载、授权、调用、观测插件（真实模块执行，能力为占位）。

**S6 无入口**
运行提示「未声明启动入口，加载成功」并正常退出。

## 七、结论

- 设计目标态**尚未开始**；缺口 15 项，集中在「宿主通道、宿主真实能力、验证」三簇。
- 设计的**支撑能力大多已就位**（能力形状与裁剪、拒绝语义、真实能力库、授权匹配、运行接线点、同步/异步形状、全绿基线），实现属既有行为延伸，而非重写。
- 实现时须对齐两处**功能性偏差**：
  1. 日志输出通道——设计要「错误级走标准错误、其余走标准输出」，当前全部走标准错误。
  2. 守护进程——设计列为不做，但当前已能真实执行插件（能力为占位）；接入真实宿主时需决定其是否同步跟进。
- 第三节列出的既有功能应作为**回归保护对象**，实现期不得破坏。
