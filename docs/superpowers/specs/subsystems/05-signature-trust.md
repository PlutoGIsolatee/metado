# Metado 签名与信任

## 6. 签名与信任（类 Android 模型）

### 6.1 机制

- **算法：Ed25519（v1 唯一）**；签名 64 字节，验签快，Rust 生态成熟。无 RSA/ECDSA/X.509/证书链 —— 信任判定在引擎外，PKI/CA 无必要
- **信封格式**：

```
.mdl = header { magic "MDL1", format_version, signer_pubkey, algorithm = "ed25519" }
     + signature（覆盖后续所有字节）
     + payload（ZIP 模块树容器：manifest + src + node_modules + wasm，§10.2）
```

- **`signer_id` = 公钥指纹**（如 sha256 截段），作为插件的稳定发布者身份

### 6.2 语义（复制 Android 结构，简化机制）

1. **载荷前独立验签闸门**：`load_plugin` 先验签（甚至不解包 payload），失败即拒
2. **签名 = 稳定身份**：signer_id 绑定插件身份
3. **同签更新（引擎强制）**：同 plugin_id 的新 bundle，`signer_pubkey` 指纹必须等于**当前存储本体**的 signer（自本体重算比对），否则拒绝 —— 防冒名覆盖，不依赖用户决策；引擎为唯一写者，本体只能经引擎入位，无须持久化首装锚；例外见 §6.4 主动轮换（须旧钥背书的新 signer，且与更新原子）
4. **引擎不裁决可信性**：只做完整性验证 + 身份比对；发布者可不可信由用户/宿主决定（对应 Android 的渠道/侧载）
5. **私钥永不入引擎**：签名私钥只在插件开发者侧，文件只含公钥与指纹

### 6.3 同签名互通（显式 opt-in）

- 以 signer 域划分存储/vfs 命名空间的第二层：

```
storage keyspace:
  私有   storage:<plugin_id>:<key>      ← 本插件专属
  共享   storage:<signer_id>:<key>      ← 同发布者（同签）共享

权限声明显式 opt-in：
  storage.<signer>.write / vfs.<signer>.read
  未声明 → 共享域不可达；同签插件默认不互通，最小权限保持
```

- 引擎需在解包验签后、权限注入前完成 `<signer>` 绑定
- 共享域基于签名验证后的 signer_id，不可伪造（验签是前置闸门）

### 6.4 主动密钥轮换（旧钥可用）

- **范围**：仅旧钥可用、能签署迁移背书的主动轮换。旧钥不可用/丢失后的迁移，以及签名 scheme 升级时的迁移，**不在本节范围**（见 §15）。
- **存在形式**：轮换证明是 payload 内与 `mdl.toml` 并列的独立条目（不混入 manifest；条目名实现定），仅轮换过渡包携带；statement 内容仅旧钥签名，只绑定 `plugin_id` 与 old signer → new signer（只绑密钥链，不绑 payload 摘要）；新钥对证明文件的覆盖来自"信封签名覆盖整个 payload"，信封格式不变（§10.2）。
- **求值与原子**：证明只在 update 路径求值，首装包内如带证明则忽略；验证顺序为验信封（新钥）→ 取当前本体 signer（重算）→ 验迁移背书（旧钥）→ 核对绑定（`statement.old == 当前本体 signer`、`statement.new == 信封 signer`、`plugin_id` 一致）→ 走正常 update 语义；任一失败则整个更新拒绝、旧版保留。
- **效力**：成功后，该 `plugin_id` 的后续更新不再接受旧钥签名（与陌生钥同等拒绝）。
- **授权不变**：更新的授权延续等语义与普通更新一致。
- **信任模型不变**：信任声明来自旧钥签名，引擎只验证、不裁决（§2、§6.2-4）。
- **旧钥作废的持久化形式**（跨卸载/重装如何延续作废，即墓碑机制）**留待进一步研究**，当前不进入设计。
