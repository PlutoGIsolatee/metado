# ADR-003：墓碑机制推迟

状态：已接受（推迟项，留待进一步研究）
日期：2026-09-23

背景：主动密钥轮换要求旧钥在成功后不再被接受；卸载后重装可能让旧钥以"全新安装"复活。需决定是否引入墓碑（deny-list / `rotated_from`）机制。

选项：
  - A：带 `rotated_from` 便车墓碑（搭 uninstall 墓碑记录，零新表）。
    优点：堵住"排障性卸载复活坏钥"。缺点：新增持久化事实类型，需定义墓碑语义（范围、清除条件）。
  - B：陌生人模型（uninstall 即信任清零，不设墓碑）。
    优点：最简单，store 只留三样。缺点：uninstall 成为信任重置操作。

决定：都不入设计，整体留待进一步研究。update 路径下旧钥拒绝与陌生钥等价已够用；跨卸载的延续问题待后续议题。

后果：§6.4 记研究项；uninstall 的信任语义未定；后续议题触发条件：出现卸载后重装的安全复核需求时重启。
