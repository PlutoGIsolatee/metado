# ADR-001：状态所有权归引擎

状态：已接受
日期：2026-09-22

背景：引擎可替换要求状态跨重启/换代延续。决策权威（谁产生治理决定）与状态所有权（谁持有并持久化结果）是两条正交轴，需明确划分。

选项：
  - A：宿主持有状态、引擎无状态（引擎是纯执行器，宿主重灌一切）。
    优点：引擎简单、可替换性天然成立。缺点：引擎的自主状态（安装记录、quarantine、驱逐、domain 超限降级）宿主无法重放，只能丢弃或伪造。
  - B：引擎持有状态、宿主仅决策（宿主下命令，引擎记住并延续）。
    优点：与"storage 是唯一真相"一致；授权跨重启延续，替换透明。缺点：store 成为替换契约核心，引擎成为信任边界一部分。

决定：选 B，因为引擎存在大量宿主无法重放的自主状态，A 会制造假权威。

后果：store 格式成为引擎间替换契约；主设计 §11.4 重划（宿主=决策权威+命令源，引擎=状态所有者+执行者）；引擎数据目录受 OS 层保护即可，store 不签名不加密；信任决策不落 store。
