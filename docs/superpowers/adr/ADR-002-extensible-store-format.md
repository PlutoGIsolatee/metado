# ADR-002：store 可扩展格式（弱契约）

状态：已接受
日期：2026-09-22

背景：ADR-001 确立引擎持有状态后，替换要求引擎间有共同的状态格式。需决定该格式的公开强度。

选项：
  - A：强契约（跨实现公开规范，任何引擎实现读写即接管）。
    优点：脱耦最彻底。缺点：引擎内部数据模型被冻结成外部规范，演进被绑住；"任意第三方引擎"短期无真实用户。
  - B：弱契约（同族版本间可迁移）+ 可扩展格式（核心 + 扩展命名空间）。
    优点：不一次冻结，"强弱"化为"核心多大"，可随版本生长；不同分支字段互不干扰。缺点：脱耦只到 Metado 边界。

决定：选 B。store 设计为自描述 + `format_version` + 可导出/导入，将来升强契约有路。

后果：store = 自描述文档、命名空间 + 字段（命名空间 = 引入字段的引擎分支标识符）；统一读取规则（认得按语义用，不认得原样保留、绝不重写、绝不据此拒绝）；只加不改，含义变更走主版本 + 迁移；主版本不认则拒绝启动；branch-id 唯一性暂不约束。
